# 工作室 FBX 角色：骨架修正与动作对接

面向 HS2MeshExporter 导出的角色 FBX。实现在 `hs2_rig_kit/fbxrig.py`，
入口是 `ops.import_character_fbx()`；UI 在 `HS2 → 动作 → 编辑对象`。

验收脚本：`tools/test_fbx_rig.py`。这份文档里的每个数字都可以用它复现。

## 1. 导出数据长什么样

FBX 里一共 781 个 Model 节点，分三类：

| 类型 | 数量 | 是什么 |
| --- | --- | --- |
| `LimbNode` | 290 | **骨架**：动画骨架 `cf_J_*` + 网格骨架独有的骨（见下） |
| `Null` | 482 | 工作室的定位/参考点（`N_Shoulder_L`、`n_body_cf`、`p_cf_body_00`…），不是骨 |
| `Mesh` | 9 | `o_body_cf` / `o_head` / `o_eyebase_L,R` / `o_eyelashes` / `o_eyeshadow` / `o_namida` / `o_tang` / `o_tooth` |

### 290 根骨其实是两套

HS2 里角色是「动画骨架 + 网格骨架」两套并存的，导出时被合进同一棵树：

- **动画骨架**（`p_cf_anim`，游戏里 602 根）：手指末节 `cf_J_Hand_Index03_L`、
  副骨 `cf_J_ArmUp01_s_L`、`cf_J_LegKnee_back_s_L` 这些都在里面，而且**带蒙皮权重**
- **只在网格骨架里的骨**：`cf_J_Eye01_s_L`~`Eye04_s`、`cf_J_pupil_s_L`、
  `cf_J_ChinTip_s`、`cf_J_Vagina_*`（二十多根）

`cf_J_Vagina_*` 这种名字里的 `.001`~`.005` 是**真的骨名**，不是 Blender 的重名后缀。

| 项 | 值 |
| --- | --- |
| 坐标 | Y-up，单位声明为 cm，实际数值 1 单位 = 0.1m |
| BindPose | 9 个 Pose 元素（每个网格一个），内容一致；每根骨一个全局矩阵，**带角色体型缩放**（这套 0.9，个别骨 0.83~0.97 非均匀） |
| BindPose 姿势 | 视导出时的姿势而定：`20261023222251` 是 T-pose，`20261023224217` 是手臂下垂的 A-pose |
| 蒙皮 | 306 个 Cluster，`TransformLink` 与 Pose 的 BindPose 一致 |

## 2. 三个坑（每一个都会让蒙皮错）

### 2.1 `ignore_leaf_bones=True` 会删掉 34 根骨

Blender 自带导入器这个选项（默认关）会去掉「没有子骨、只用来标记父骨末端」的
叶子骨。可 HS2 的叶子骨是**真正带权重**的：

| 少了什么 | 后果 |
| --- | --- |
| `cf_J_Hand_Index03/Middle03/Ring03/Little03/Thumb03` ×2 | 指尖不跟手，手指被拉长 |
| `cf_J_ArmUp01_s`、`cf_J_ArmElboura_s`、`cf_J_LegKnee_back_s`、`cf_J_LegUpDam_s` | 上臂/大腿内侧蒙皮错位 |
| `cf_J_Eye01~04_s`、`cf_J_pupil_s`、`cf_J_ChinTip_s` | 眼球/下巴不跟头 |
| `cf_J_Vagina_*` | 会阴区域被撕开 |

开着它导入 → 256 根骨、116 个顶点组；关掉 → **290 根骨、126 个顶点组**，
和 Better FBX 完全一致。所以导入必须 `ignore_leaf_bones=False`。

### 2.2 BindPose 的缩放被 `normalized()` 丢掉

```python
bone_matrix = parent_matrix @ self.get_bind_matrix().normalized()
```

`normalized()` 把 3×3 归一化，BindPose 的 0.9 体型缩放没了，于是**所有骨头一起
比蒙皮大 1/0.9 ≈ 11%**。看着像"某一节骨错位"，其实是整副骨架放大了一档：
动画绕放大后的枢轴转，网格就被拉成带状。

### 2.3 `.001` 不是 Blender 的重名后缀

`cf_J_Vagina_V.001`、`cf_J_Vagina_L.005` 是 HS2 生成的真实骨名。按"去掉 .001 再查"
会去查一根不存在的骨，退回到导入器的错位 rest —— 那 22 根骨就差了 1.3 单位、
还翻了 180°。查表时**必须先按原名查**。

## 3. 修法

### 3.1 rest 直接照搬 BindPose

```python
targets[bone] = bind_pose_global_matrix[bone]     # 不转基！
```

- `head` ← BindPose 平移，朝向 ← BindPose 旋转的 Y 列，`roll` ← `align_roll(Z 列)`
- 骨长：非叶子骨取所有子骨 head 的平均位置，叶子骨沿父骨延长一倍
  （和 Better FBX 的"自动骨朝向"一致，纯显示）
- 全部 `use_connect = False`，否则改子骨 head 会被父骨 tail 拽回去
- 查表先按原名、再按去掉后缀的名字

Blender 把轴转换（Y-up → Z-up）挂在**骨架物体**的 `matrix_world` 上，骨头自己的
rest 矩阵就是 FBX 的全局矩阵，所以直接照搬、不要自己再转一次基（转了会整体躺倒 90°）。

丢掉缩放不影响形变：形变只跟"骨头位置 + 旋转"有关，位置摆对就完全对齐。

### 3.2 姿势对齐

工作室 bind 可能是 A-pose，插件默认骨架 `p_cf_anim` 是手臂平举的 T-pose。
导入后把每根骨的世界朝向抄成默认骨架的朝向（`clip=None` 的 `fbxrig.apply`），
她的站姿、手型就和插件默认角色一致。姿势改乱了可以点「对齐默认骨架姿势」重来。

朝向必须用 **Unity 空间的原始矩阵**（`_frame_worlds` 不做 `mat_to_blender`），
因为 FBX 骨的 rest 就活在那个空间里；用 Blender 空间的矩阵会整体差 90°。

### 3.3 套动作

游戏动作是「骨骼世界朝向的绝对值」。每帧每根骨：

```python
qt  = Q_game(bone)                     # 目标世界朝向（Unity 空间原始矩阵）
pos = 父骨姿势 @ (rest 局部偏移)        # 位置由链决定，保持角色自己的骨长
basis = A^-1 @ (world[parent]^-1 @ M)  # 反解成 matrix_basis
```

- 朝向绝对、位置刚性 —— 不会出现「骨长按默认骨架算」导致的拉伸
- 有位移轨道的骨用**父骨空间的局部增量**，不是世界坐标：那 97 根骨的位置轨道
  大多是静止的，换成绝对位置等于把它们钉在 bind 位置，手一转就把手指撕开
- 根位移按身高比缩放（头骨-髋骨距离之比），并且只乘这一个比例 ——
  游戏数据是原始单位、骨架局部也是原始单位，骨架物体的缩放不能混进来
  （混进来会让 0.01 缩放的骨架根位移差 10 倍）
- 网格骨架独有的骨（眼球、vagina）不在 `p_cf_anim` 里，跟着父骨刚性走

### 3.4 L/R 配对

工作室导出把 X 轴镜像了：FBX 里 `cf_J_Hand_L` 落在 **+X**，游戏里在 **-X**。
按名字硬套会让手臂横穿身体，所以按**世界 X 位置**配对（两边都换算成原始单位再比）。

### 3.5 根骨收口：p_cf_anim 必须是根

工作室在 `p_cf_anim` 外面又套了一层 `BodyTop`（head 在原点、唯一子骨是
`p_cf_anim`）。它没有任何蒙皮权重，但会让骨架根骨变成 `BodyTop`，和游戏里的
`p_cf_anim` 对不上（导出到 UE 时根骨名字也不对）。

导入时自动删掉 `p_cf_anim` 之上的骨：先把 `p_cf_anim.parent` 置空
（edit bone 用绝对坐标，位置不会变），再删上层骨。为了安全，上层骨只要有
蒙皮权重就一律不动。290 根 → 289 根。

### 3.6 骨骼缩放要一起传

HS2 的动作不只转骨头，还会**缩放**：手肘/膝盖的 `*_dam` 补偿骨在动作里会被
拉到 1.05~1.23（实测 `cf_J_ArmLow02_dam` 最大 1.234，`cf_J_Kokan` 会到 0.953）。
只传旋转的话关节会塌、裆部体积不对。

做法：取游戏数据里该骨的**世界缩放**，除以它自己的静止缩放，得到形变倍率，
直接乘进目标世界矩阵：

```python
m = T(pos) @ R(朝向) @ S(世界缩放 / 静止缩放)
basis = A^-1 @ (parent^-1 @ m)     # decompose 出来的 scale 一起写进关键帧
```

实测（`adv_action_00_08` 第 12 帧）：`cf_J_ArmLow02_dam` 世界缩放
游戏 = 1.093，导入后 = 1.093 ✓（改之前是 1.000）。

全部骨都写 scale 通道：会变的按帧写，不变的写一个常数帧 ——
避免从一个带缩放的动作切过来时残留旧值。扫了 6 条动作，缩放范围
`[0.953 .. 1.234]`，没有 0 / 负数 / 爆表。

## 4. 和 Better FBX 的逐项对比

用 Better FBX（桌面版默认设置）导入同一份 FBX 当参照：

| 检查项 | 结果 |
| --- | --- |
| 骨名集合 | 290 = 290，不差一根 |
| rest 骨头位置 | 最大差 **0.0000** 单位 |
| rest 骨头朝向 | 中位 0.0°，只有 4 根眼球骨差 5°（非均匀缩放分解差异） |
| 父子关系 | 290/290 完全一致 |
| 顶点组 | 126 = 126，权重逐顶点比对 **0 处不一致**（32313 项） |
| 蒙皮顶点数据 | 10303 个顶点，最大差 **0.00000** |
| 套同一条动作后的顶点位置 | 最大差 **0.0012 单位**（0.12mm，来自那 4 根眼球骨） |
| 9 个网格（头/眼/睫毛/眼泪/牙/舌）| 最大差 < 0.005 单位 |

## 5. 验收

```bash
blender -b --factory-startup --python tools/test_fbx_rig.py -- <角色.fbx>
```

用插件默认角色跑同一批动作当参照，比较网格边长伸缩比：

| 动作 | FBX 角色 p99/max/>1.5% | 默认角色 p99/max/>1.5% |
| --- | --- | --- |
| mc_f_move_07_L | 1.18 / 2.17 / 0.01% | 1.18 / 1.49 / 0.00% |
| action_44 | 1.27 / 14.58 / 0.29% | 1.29 / 4.18 / 0.26% |
| adv_action_05_01 | 1.27 / 2.70 / 0.30% | 1.28 / 2.55 / 0.31% |
| sleep_09 | 1.42 / 5.99 / 0.76% | 1.45 / 2.99 / 0.83% |
| f_custom_pose_03 | 1.41 / 4.08 / 0.64% | 1.42 / 3.02 / 0.70% |

中位伸缩比 1.000，p99 与默认角色同档。`action_44` 第 48 帧那几倍拉伸在默认角色上
同样存在（`cf_J_Kosi02_s`+`cf_J_LegUp01_s` 跨腿大张），是动作本身的极限姿势；
FBX 角色多出来的那几倍发生在会阴——那块区域由网格骨架独有的 `cf_J_Vagina_*` 驱动，
`p_cf_anim` 的动作数据里没有这些骨，只能跟着骨盆刚性走。

## 6. 不做什么

- 不做重新绑定（rebind）到默认骨架，也不复制默认骨架的 rest
- 不移动单根骨"看起来对上"
- 不把角色网格镜像回来（动作按 X 位置配对后已经一致）
