## 1. 这一版修掉的三个真问题

### 1.1 IK 打帧偏差 0.22~0.33 m —— 根因不是 `use_tail`

上一版猜是 `use_tail`，其实只猜对了一半。真正有三层原因：

**(a) `use_tail` 的语义。** 实测（`use_tail` 两种取值 + 两种目标位置）确认：

- 目标点**永远是目标骨的 head**，不是 tail；
- `use_tail = True` → 链末端取约束骨的 **tail**；
- `use_tail = False` → 链末端取约束骨的 **head**，而且这根骨自己不参与解算。

所以「把控制器 head 放在脚踝 + `use_tail=True`」必然差一个控制器长度，
手部控制器长度 0.29，脚部 0.08，正好对上观察到的偏差量级。

**(b) 骨骼长度是错的。** `bdata` 里 bone 的 tail 长度取「最近的子骨距离」，
但 HS2 的腿在 `LegUp00 → LegLow01` 之间还挂着 `LegUp03` 之类的小骨，
结果大腿长度算成 0.20 m，实际髋到膝是 0.42 m。Blender 的 IK 按骨长算可及范围，
链长 0.668 < 实际 0.888，目标永远够不着，解算器只能把腿拉直硬怼。

**(c) 骨骼朝向是"假"的。** HS2 静止姿势下所有骨的局部旋转都是单位四元数，
tail 全部朝上（一把梳子）。IK 解算器看到的是一条朝后的直线，不是腿。

三个叠加，才有了 0.35 m 的偏差。

**结论**：不能直接在游戏骨上做 IK，也不能改游戏骨的 tail（会破坏静止朝向，
导出的局部旋转就和游戏对不上）。改用**独立的机械骨层**：

```
IKB_thigh_L  髋→膝  ┐  形状与真实关节一致，IK 挂在这条链上
IKB_calf_L   膝→踝  ┘
CAR_thigh_L  挂在 IKB_thigh_L 下，静止朝向 = 游戏骨
CAR_calf_L   同上
```

游戏骨用 Copy Rotation（世界空间）跟随 CAR 骨。CAR 骨的静止朝向与游戏骨一致，
所以它的世界旋转恰好是"机械骨相对自身的增量"，游戏骨拿到就是纯增量。

### 1.2 极向角解出随机值

第一版用「旋转大腿 30°」合成弯曲再扫极向角，但：

- `matrix_basis` 是**骨骼本地空间**，直接塞世界轴，手臂（骨轴朝侧面）就变成了
  绕自身轴的扭转，关节几乎不动 → 误差地形是平的 → 解出 ±90° 这种随机值；
- 清掉 action 之后姿势**还停在最后一帧**，所谓"静止姿势"是假的。

修法：弯曲轴 = `骨链方向 × 期望方向` 再转成本地轴；求解前把整副骨架的
`matrix_basis` 归零。修完腿解出 -90、手臂 0/-180，和真实动作上的最优角
**完全一致**。

### 1.3 头部飘在天上

两个原因：

- 头部骨骼树的顶层节点 `parent = None`，插进骨架后成了**根骨**，不跟 `cf_J_Head`
  走 → 必须显式挂到 `cf_J_Head` 下；
- 头部网格的 `m_BindPose` 是相对**头 prefab 根**的，不是相对骨架根，
  顶点要先乘 `cf_J_Head` 的世界矩阵（实测差了 1.6 m）。

修完头身 z 区间：身体 0.012~1.603，头 1.554~1.763，衔接正常。

### 2.2 打帧与吸附

- `key_targets`：逐帧读 FK 姿态 → 摆控制器 → 打 location + rotation 关键帧

- 有父级的手趾控制器用显式父矩阵算 basis（`_set_child_world`），
  否则同一帧里父级还没刷新，算出来的 basis 是错的（脚趾会翻 180°）。
- 吸附：`snap_ik_to_fk` / `snap_fk_to_ik`，实测跳变 0.0000 m。

FBX 小一半。烘完 IK 自动置 0，约束清零（机械骨上剩 4 条 IK 约束，

## 7. 第四轮：修用户反馈的三个问题

### 7.1 控制器看不见 ★
两个原因：
1. `HS2_WGT` 集合设了 `hide_viewport=True` → 物件不进 depsgraph。
2. 更重要：**骨架没开「在前面」**，控制器在身体内部，被网格完全挡住。
修法：`arm.show_in_front = True` + 按 Rigify 的做法把 WGT 集合从视图层
`exclude`（物件不显示，但 custom shape 照画）。

### 7.2 加载游戏动作出现「IK 扭曲」★
`_mute_rig(False)` 会把**所有** HS2_ 约束解静音，包括关节补偿 `HS2_FIX_*`。
导入动作时 `key_targets` 结束会解静音 → 14 条补偿约束被打开 → dam 骨按近似
比例转 → 膝盖/手肘/胯的网格被拧。修法：`_mute_rig` 跳过 FIX 约束，
补偿状态只由用户的开关决定。

### 7.3 两个重定向都扭曲 ★★
**Mixamo**：源骨架物体带 +90°X 旋转（Mixamo 是 Y-up、厘米制），我原来在
**骨架空间**里搬旋转 → 坐标系没对齐，整体拧掉。改成**世界空间**取增量；
另外补了「静止朝向对齐」：源是 A-pose、HS2 是 T-pose，直接搬增量会差一个
静止角，按每根骨的「主链子骨方向」算对齐旋转先补掉。
修完：头 0~1°、脚 15~27°、手 15~30°（剩下的是体型差异）。

**VMD**：手臂 A→T 补偿的**符号反了**（原来把手臂抬高 35°，应该压低 35°），
而且加在肩关节上（应该加大臂）。另外把 `腰` 的映射删了 —— MMD 的 腰 在
下半身之下带动上半身，HS2 的 Kosi01 在 Kosi02 之上带动腿，方向相反。

### 7.4 其他
- 骨骼/控制骨一律按世界矩阵**严格**建（tail+align_roll 有 1~3° 残差）。

## 8. 第五轮修复：人物翻倒 90° + 控制器面板报错

### 8.1 人物向前转 90°（严重回归）
上一轮为了「精确静止朝向」把骨骼创建改成 `eb.matrix = 世界矩阵`。

（静止姿势看不出来：此时 pose == rest，蒙皮恒等；一旦有动画就全错。）

修法：回到 `head/tail + align_roll`（根骨得到单位旋转）。
校验：`matrix_local` 与游戏世界矩阵逐骨比对，602 骨里只剩 4 根重名节点
（`GameObject`）不匹配，根骨 0.00°。

### 8.3 自检补强

## 9. 第六轮：找到「一直不成功」的真正原因 + Blender 5.2 兼容

### 9.1 为什么改了没效果（根因）
排查发现两件事，都能解释「我这边还是没有成功」：

1. **Blender 里根本没有装插件。** 全盘搜索只在回收站里找到一份旧的

   用户跑的一直是旧副本 / 或者压根没装上，而我改的是
   `D:/game/HS2/HS2AnimKit/hs2_rig_kit` 源码 —— 两边对不上。
2. **用户已经升级到 Blender 5.2**（4.2 / 4.5 只剩残留目录）。5.2 换成了
   Python 3.13，而且移除了不少旧 API，插件在上面直接报错。

修法：把插件以**目录联接（junction）**挂进 Blender 的 addons 目录，
指向源码目录。以后改完代码重启 Blender 就是最新的，不用再手动装 zip：

```
C:/Users/123/AppData/Roaming/Blender Foundation\Blender\5.2\scripts\addons\hs2_rig_kit
    -> D:/game/HS2/HS2AnimKit/hs2_rig_kit
```

旁边有个刷新按钮（`script.reload`）可以不用重启就重载插件。

### 9.2 Blender 5.2 的三个不兼容点

**① `_brotli` / `lz4` 二进制是 cp311 的**
5.2 内置 Python 3.13，加载不了。补了官方 cp313 wheel 里的 4 个 `.pyd`
（`_brotli`、`lz4/_version`、`lz4/block/_block`、`lz4/frame/_frame`）。
cp311 的保留，所以 4.x 也能用。

**② `Action.fcurves` / `Action.groups` 被彻底移除**
5.x 只剩分层 action：`action.layers[0].strips[0].channelbag(slot).fcurves`。
新增 `hs2_rig_kit/compat.py` 做兼容层，对外只暴露一个「拿 fcurve 容器」的
函数 `bag(act, arm)`，调用方不用关心版本。涉及 `anim.py` / `retarget.py` /
`rig.py` / `ops.py`。

**③ `Bone.select` 被移除**
烘焙选骨那处改成 `PoseBone.select`（4.x 也有，向前兼容），两个都试着设一遍。

## 10. 第七轮：IK 稳定性 / 控制器重做 / 两个重定向修正 / UI 精简

### 10.1 IK「拖远了就扭曲」的真正原因
先做了两组诊断（`tools/diag2.py` / `diag3.py`），量出来的事实：

| 现象 | 数值 |
|---|---|
| 脚往前/侧向拖，膝盖完全不动 | 弯曲 **0.3°**（腿被锁死伸直） |
| 脚抬高 1 m | 膝盖弯 **193°** —— 反折了 |

根因两条：
1. **完全没设关节限制** → 膝盖可以往任意方向弯，抬到头顶就翻过去；
2. 测试中发现一个坑：Blender 的 `use_ik_limit_*` 对 **IK 约束的 owner 骨
   （链末端）不生效** —— 属性设上了 `[-20,170]`，实测照样 193°。
   改成在 IK 之后叠一层 `LIMIT_ROTATION` 才真正夹住（166.7°）。

另外顺手踩了两个坑：
* `KinematicConstraint.use_tail` 不是「目标骨的尾巴」，而是「**链条末端算不算
  owner 的 tail**」。设成 False 等于让膝盖去够目标点，脚直接拖不动（3 cm）。
* `ik_stiffness` 是「抵抗旋转」，给到 0.35 就让「吸附后开 IK」跳 16 cm。
  默认全 0。

最终配置：膝盖 `LIMIT_ROTATION` X∈[-20°,170°]、Y/Z 锁死；髋/肩不限制
（锁了会让吸附跳）。自检：拖脚位移 (0,0,0.1)、吸附后 0.0000 m、反折被夹住。

### 10.2 控制器为什么全是「朝前的竖圆环」
HS2 是纯枢轴骨架，**所有骨静止旋转都是单位矩阵**，也就是每根骨的本地
X/Y/Z 就等于世界 X/Y/Z。旧的 `widgets._ring()` 画在**本地 XZ 平面**
（法线 = 本地 Y = 世界 Y = 前后）→ 圆环全是竖着的、面朝前。

重写 `widgets.py`：
* `ring()` —— **水平圆环**（本地 XY 平面），躯干 / 腿 / 头；
* `ring_side()` —— 竖直圆环（法线沿 X），手臂（手臂沿 X 伸出去）；
* `foot()` —— 脚掌轮廓（本地 XZ，跟着脚背倾斜）+ 脚尖箭头；
* `arrow()` —— 根控制器：贴地大环 + 正前方箭头；
* 统一带四向刻度，朝向一眼可见。

另外把 **693 根变形骨默认隐藏**（`HS2 变形` 集合），只留控制环 ——
原来满屏八面体碎块，完全盖住控制器。

### 10.3 两个重定向的扭曲

**Mixamo（脚踝被拧歪）**
`mixamo_tracks` 里有一段「静止朝向对齐」：用 `rotation_difference` 把目标骨的
主链方向转到源骨方向。问题是 `rotation_difference` 只对齐**朝向轴**，
**不含绕该轴的 roll（扭转）** —— 脚踝就这么被拧了。
按公式 `目标世界旋转 = Δ · R_dst_rest`（HS2 的 R_dst_rest 是单位矩阵），
这段对齐本来就不需要。去掉后：手臂动作从「垂着」变成正确的「举起交叉」，
脚踝自然，贴地误差 -0.025 m → 0.000 m。

**VMD（上下半身在腰断开）**
MMD 标准骨架的躯干层级：
```
グルーブ → 下半身 → 腰 → 上半身
          └ 足
```
而 HS2 是：
```
cf_J_Hips            ← 同时带腿和上半身
├── Kosi01 → Kosi02 → 大腿
└── Spine01 → ... → Neck
```
原来把「下半身」映射到 `Kosi02`（只带腿），还把「腰」整个丢了 ——
躯干旋转传不上去，人就从腰断开。改成 `腰 → cf_J_Hips`、
`下半身 → cf_J_Kosi02`、`上半身 → cf_J_Spine01`。
另外 VMD 里的骨位置只写进根骨（其它骨的位移来自 MMD 的 IK 解算，
直接搬到 HS2 会把骨节拉开）。

渲染验证（`tools/render_retarget.py`，5 帧均匀取样）：
VMD 舞蹈动作连贯、脚踩地；Mixamo 的 Stomp 是标准的抬腿踩踏姿势。

### 10.4 UI 精简
* **去掉重复的 IK 开关**：主面板只显示 IK 状态，开关统一放在「控制器」面板；
* **扫描动作库按钮变小**（只留刷新图标），未扫描时给一次「开始扫描」；
* **动作选择改成下拉框**（`EnumProperty`，点开可直接打字搜索），
  滑条保留 —— 两种方式都能用；枚举带缓存，1261 项不会每帧重排；
* **滤掉不适配的动作**：扫描时算每个动作的「骨骼绑定匹配率」
  （binding 的 path hash 能不能在骨架里找到）。1261 个动作里
  **1232 个完全适配**，挑出的 29 个全是道具动作
  （`sao_fishing_*` 钓鱼、`action_54_item`、`open` 开门）。
  面板上有「也显示不适配的动作」开关。扫描顺带从 20 s 降到 **4.9 s**。

## 11. 参考 MMDD（别人的 HS2 舞蹈插件）后的修正

朋友给了个 `.nbmod`（7z 包），解开是 **MMDD v2.9.4** —— 一个成熟的
HS2 舞蹈演出插件，带 Python 源码和一堆 `chara_*.ini` 骨骼映射表。
看了它的做法，修正了我们三处：

### 11.1 它的整体架构（和我们的不同点）
MMDD 不是"直接把 MMD 动作套到 HS2 骨上"，而是：
1. 在 HS2 骨架上**造一棵虚拟的 MMD 骨架**（`BonePosition` 定义每根虚拟骨
   挂在哪个 HS2 骨的位置上）；
2. VMD 驱动这套虚拟骨；
3. 虚拟骨通过 **global sync** 把世界变换同步回 HS2 实际骨（`BoneWeight`）。

好处是能 100% 复刻 MMD 的层级和 IK；代价是复杂。我们走的是"直接映射 +
局部补偿"，效果够用。

### 11.2 躯干映射（我们错了）
MMDD 的 `chara_default_2.0.ini` 里：
```
GROOVE    = グルーブ
BACK_HIPS = GROOVE:腰         → 位置 = cf_J_Siri_s_L / cf_J_Siri_s_R 中点
HIPS      = BACK_HIPS:体の重心 → cf_J_Hips
SPINE1    = HIPS:上半身       → cf_J_Spine01
WAIST     = HIPS:下半身       → cf_J_Kosi01      ← 注意是 Kosi01，不是 Kosi02
```
而且它有两个 **腰キャンセル** 骨：
```
BACK_HIPS_C_R = WAIST:腰キャンセル右 :t:tr,-1,BACK_HIPS
```
`tr,-1` = **反向 track 腰**。作用就是：**腰的旋转只带动上半身，不让腿跟着转**。

我们原来把「下半身」映射到 `Kosi02`、又把「腰」丢掉，所以腰一扭躯干就断。
现在改成：
* `腰 → cf_J_Hips`、`下半身 → cf_J_Kosi01`；
* 给 `Kosi01` 左乘一个腰旋转的逆（`CANCEL_MAP`），复刻「腰キャンセル」。

### 11.3 膝盖限制直接抄它的数值
MMDD 的 `[BoneIKSet_1]`：
```
SOLVER=MMDIKSolverLeg
LIMITS=(((0.5, 180), (0, 0), (0, 0)), None)
MIN_KNEE_ROT=1
```
`(0.5°, 180°)` 是膝盖的 X 范围，Y/Z 都是 0 —— **和我们上一轮的结论一致**，
只是它的下界是 0.5° 而不是负角度（不允许任何超伸）。已改成这组值。

### 11.4 其他可以借鉴的（暂未做）
* **手臂 A-pose 补偿是 32°**（我们是 35°，可调）；
* `PrepareBoneBeforeCreateDummyBone` 里对腿骨做了 1~3° 的轴向微调
  （`cf_J_LegUp00` -1.12°、`cf_J_LegLow01` +3.5°、`cf_J_Foot01` -2.38°），
  用来消掉 HS2 和 MMD 骨架的轴向差 —— 想做「完全一致」的话可以照做；
* 足 IK 是 **3 段**（足首→ひざ→足）+ 单独的**脚趾 IK**（つま先→足首）；
* `chara_*.ini` 里还有 `DIVA` / `HMVR` / 不同身高体型的映射，
  说明不同模型需要不同配置 —— 我们目前只支持标准女骨。

## 12. 第八轮：按 MMDD 架构实现「虚拟 MMD 骨架」（完全一致）

用户要求「先做到和这个 mmd 插件完全一致」。MMDD 的核心做法不是把 VMD 直接套到
HS2 骨上，而是**在 HS2 骨架上造一棵虚拟 MMD 骨架**，VMD 驱动它，再按 ini 的
`BoneWeight` 把世界变换同步回 HS2 实骨。这样才能 100% 保留 MMD 的层级、IK、
扭转骨、腰キャンセル。

### 12.1 新增的三个模块

| 文件 | 作用 |
|---|---|
| `hs2_rig_kit/mmdcfg.py` | 解析 MMDD 的 `chara_*.ini`（BoneDefine/BonePosition/BoneWeight/BoneIKSet/BoneRotAxisAdjust/扭转） |
| `hs2_rig_kit/mmdrig.py` | 建虚拟骨架、配 IK/扭转、按权重同步回 HS2、把 VMD 写进虚拟骨 |
| `_ref/mmdd/` | 备份了 MMDD v2.9.4 的源码与 24 套角色 ini（重要参考资料） |

`HS2_OT_import_vmd` 新增两个参数：
* `use_dummy`（默认 **开**）——「用虚拟 MMD 骨架（和 MMDD 一致）」；
* `chara`——角色骨骼配置下拉框（24 套 ini）。

关掉 `use_dummy` 就退回老的「直接映射」路径。

### 12.2 踩到的最大一个坑：虚拟骨的 rest 朝向

第一版把虚拟骨的 tail 指向子骨（解剖学朝向），于是它们的 **rest 世界朝向不是单位矩阵**。
VMD 的旋转是「相对 MMD rest 的本地旋转」，直接当成「本地旋转」写进虚拟骨，
世界朝向就全乱了 —— 实测**整副人向前躺倒（俯仰 84°）、脚悬空 1.16 m**。

试过「每根骨左乘自己的 rest 逆」，结果更糟（116°）—— 因为 VMD 的本地旋转是相对
**父链 rest** 的，而虚拟骨的 rest 来自 HS2，父子链也对不上，单骨逆乘反而过校正。

**正解：让每根虚拟骨都取单位矩阵 rest**（tail 沿 +Y、roll=0）。
这样「本地旋转 = 世界旋转」，VMD 的本地旋转写进去后世界朝向正好等于 MMD 世界朝向，
再经 `world → world` 同步到 HS2（HS2 骨 rest 本身就是单位矩阵）即完全正确。

代价：虚拟骨全朝 +Y，IK 链几何靠自身长度撑。但最终同步给 HS2 的是**世界朝向**，
而 HS2 骨有正确的解剖 rest，所以输出姿势是对的。实测：

```
俯仰 2.9°（站立）  脚底 +0.012 m（贴地）
```

### 12.3 贴地的坑

虚拟骨架模式下 `cf_J_Root` 的位置被 `MMD_ROOT` 的 `COPY_LOCATION` 约束接管了，
所以「平移 cf_J_Root 的 location.z 曲线」这个老贴地办法**完全无效**（脚陷进地里 0.169 m）。
改成贴地作用在 `MMD_ROOT` 上（它带动整条虚拟骨链，进而带动 cf_J_Root / cf_J_Hips）。
`retarget.set_root / snap_to_ground / snap_to_ground_per_frame` 都加了 `bone` 参数。

### 12.4 Mixamo 被虚拟骨污染

先导入 VMD 虚拟骨架、再导入 Mixamo 时，残留的 `MMDD_ROT_*` 约束（world→world、
REPLACE）把 Mixamo 的动画整个盖掉 —— 表现为「Mixamo 一动不动」。修法：Mixamo 与
直接映射 VMD 在开始时都先调 `mmdrig.clear(arm)` 清掉虚拟骨和 MMDD 约束。

### 12.5 验证（Blender 5.2.2）

### 12.6 仍与 MMDD 有差距的地方
* **IK 解算器不同**：MMDD 用自写的 `MMDIKSolverLeg`（按 MMD 语义），我们用 Blender 的 IK。

* **只支持标准女骨**：MMDD 的 `chara_DIVA` / `HMVR` 等是针对不同体型的，我们目前

## 13. 第九轮：修复「生成控制器后脚变形」

## 15. 第十一轮：修复「腿部反折、肩膀凹陷」

### 15.2 根因：rot_adjust 的轴系和乘法顺序都错了

rotV = adjustAxis(rotV);                    // 默认 spec "-x,y,-z"（MMD→Unity 换基）
quaternion = Quaternion.Euler(rotV) * self.rotAdjustment;   // **后乘**

我犯了两处错：
1. **前乘**（`pre @ q`）—— 官方是后乘（补偿绕骨骼本地轴）；前乘把 ±32°
   加到了世界轴上；
2. **轴系**：ini 里的 `r,0,0,-32` 是 **Unity 轴系**（Z=前后）。Unity 是
   Y-up、Blender 是 Z-up，直接 `Euler(0,0,-32)` 等于绕**竖直轴**转 32°。
   正确做法：先在 Unity 系建四元数（Unity 欧拉顺序 ZXY = Ry·Rx·Rz），
   再做和 VMD 旋转同样的基变换（绕 X +90°，mathutil.to_blender_quat）。

修完对比：ArmLow 278.8° → **41.1°**（残差是两条路径手臂补偿机制本就不同：
直接映射是世界 Y 前乘 35°，官方是肩 -10°+腕 -32° 本地后乘）。

## 18. 第十三轮：足 IK 从零重写（v2.5.0）

### 18.1 之前一直不生效的三个根因（逐个挖出）
1. **腿长用了虚拟骨的 0.05m 假长度** —— `_bone_len` 取的是虚拟骨

   必须用 **HS2 实骨**长度（大腿 0.420m / 小腿 0.468m）。
2. **IK 目标没算 pose 位移** —— `world[IK_FOOT]` 只用了静止 head，
   没加 VMD 足ＩＫ 的位移（p_now），目标停在原地。
3. **世界矩阵把 `matrix_local` 当相对父用** —— Blender 的
   `Bone.matrix_local` 是**骨架绝对空间**，当相对父用会双重累加父链，
   髋飞到 6.5 米高空。正确做法：相对父偏移 = 绝对头 − 父绝对头。

### 18.2 正确实现（复刻 MMDIKSolverLeg）
```

  1. FK 全链算完（含 track/twist）→ 得每骨世界矩阵
     （位置 = 相对父偏移 + VMD 位移，旋转 = 逐帧本地旋转）
  2. 每条腿：H=髋世界位置，T=足ＩＫ 世界位置，L1/L2=HS2 实骨长
  3. 膝盖弯角（余弦定理）：180° − acos((L1²+L2²−d²)/(2·L1·L2))
     → 小腿本地绕 X 旋转该角（0°=伸直）
  4. CCD 迭代（6 次，步长上限 114.6°）：大腿绕世界轴旋转，
     让「髋→踝」对准「髋→目标」
  5. 大腿局部 = 父世界旋转⁻¹ @ R_thigh；小腿局部 = 膝盖弯角
  6. D 骨 track(1) 同步（否则 D 骨还是 FK 旧值）
```

## 22. 第十六轮：手臂轴倾校准（v2.7.0）——「姿势怪」的真正原因

### 22.1 为什么又去翻别人的代码

用户实测游戏里的 **HS2_VMDPlayPlugin 0.3.4**（BepInEx，配 MMD4URuntime.dll）
比我们的实现精准得多，「基本没有出现扭曲」。注意这跟之前参考的 MMDD
（CharaAnime.dll + vmdlib.py）**不是同一套**：MMDD 走 ini 虚拟骨架，
VMDPlayPlugin 直接驱动 HS2 原生骨。两套都反编译了，差异如下。

### 22.2 VMDPlayPlugin 的骨架思路（ResetBoneNameMap）

它只映射 80 根骨，且是**直接驱动**：

```
cf_J_Spine01 ← 上半身      cf_J_Kosi01 ← 下半身
cf_J_Spine02 ← 上半身2     cf_J_LegUp00/S ← 足
cf_J_Spine03 ← 上半身2先   cf_J_LegLow01/S ← ひざ
cf_J_Neck    ← 首          cf_J_Foot01/S ← 足首
cf_J_Head    ← 頭          cf_J_Toes01/S ← つま先
```

虚拟层只有 4 根：`cf_J_Root/_dummy_root(全ての親)/_dummy_center(センター)/
_dummy_groove(グルーブ)/_dummy_hips(腰)/cf_J_Hips`。

### 22.3 真正的差异：`BoneAdjustment.GetAdjustedRotation`

```
e = baseRot.eulerAngles            # Unity ZXY 分解
e = adjustAxis(e)                  # spec 重排（"-x,y,-z" 之类）
if rotAxisAdjustment:              # ← 我们完全没实现这一支
    q = AngleAxis(e.y, axisY) · AngleAxis(e.x, axisX)
        · AngleAxis(e.z, axisZ) · rotAdjustment
else:
    q = Euler(e) · rotAdjustment
axisX/Y/Z = Euler(axisAdjustment) · {right,up,forward}
```

`QuickAdjust.Set()`（默认值 Settings：Shoulder 8 / UpperArm 30 / LowerArm 0）：

| 骨 | 固定旋转 rotAdjustment | 轴倾 axisAdjustment |
|---|---|---|
| 肩 L/R | +(±sh) | — |
| 大臂 L/R | +(±au) | ∓sh |
| **小臂 L/R** | +(±al) | **∓(sh+au)** |
| **手 L/R** | — | **∓(sh+au)** |

代入 ini 的值（肩 10、大臂 32、小臂 0）就是 ∓10 / ∓42 / ∓42 ——
**正好等于 ini 里被注释掉的那几行**：

```
;UPARM_R=r,0,0,-32,a,0,0,10
;LOWARM_R=a,0,0,42
;HAND_R=a,0,0,42
```

ini 作者写了 a 模式又注释掉，插件是开着的。我们只实现了 `r`，所以
**小臂和手少了 42° 的轴倾**：肘部绕未倾斜的本地 X 轴弯，而手臂已经被
补偿旋了 42°，弯出来的方向就是拧的 —— 这正是「胳膊扭 / 手腕像扁片」。

### 22.4 等价化简

因为 `AngleAxis(a, R·ax) = R · AngleAxis(a, ax) · R⁻¹`，三个分量夹出：

```
q_adj = R · q · R⁻¹ · rotAdjustment        (R = Euler(轴倾角))
```

实现就按这个式子做**共轭**，不必逐轴重建，也不会引入欧拉分解误差
（`boneadj.py` 里同时保留忠实移植版，供校验）。

### 22.5 顺手确认的两件事（都没改）

* 旧 `_unity_euler_to_blender` 缺 Y-180 手性翻转，和 `mmd_quat_to_blender`
  差一个符号（Euler(0,0,32) 差 64°）。**但实测这个符号是对的**：HS2 静止
  是 T-pose（大臂方向 (-1,0,0)，与竖直 90°），-42° 才是把手臂放下来成
  A-pose，+42° 会举到水平以上。所以不能"顺手修正"，改了反而错。
* 插件对 `cf_J_Neck` 有 `rotationScale = 0.5`（颈部旋转减半）。实测首的
  旋转平均 15°、最大 41°，减半差异有限；且 MMDD 不做这个，属于插件的
  个人口味，暂不跟进。

### 22.6 验证（A/B 三向渲染）

帧 112 / 400 / 600，分别用 无轴倾 / 正 / 负 渲染对比：

   x/y/z/r 四条曲线逐通道采样，二分 10 次、容差 0.001，和 MMDD 完全一致。
2. **四元数写 fcurve 的通道顺序错了**：`mathutil.to_blender_quat` 返回
   `(x,y,z,w)`，旧代码直接 `q[i]` 灌进 Blender 的 `(w,x,y,z)` 曲线。
   结果静止的 ROOT 变成 180°Z、整副骨架拧着。这是「怎么看都不对」的
   最大单一原因。
3. **单位换算 0.08 是错的**：MMDD 是 `AxisScale 0.832 × 角色缩放 0.1` =
   **0.0832**。旧值短 4%，1 m 位移差 4 cm，足 IK 目标也一起偏。
4. **位置符号/基准错了**：MMDD 的 `GetAdjustedPosition` 是
   `basePosition + (-x,y,-z) * positionScale`；旧代码只写了 `pos*unit`，
   而且把 `basePosition` 也写进 Blender 的 `pose.location`，导致
   センター/足 IK 被抬高了一倍（实测脚离地 0.58 m）。
5. **足 IK 目标算错**：旧代码用 `ROOT_world + VMD足IK位置`，漏了
   `IK_ROOT` 的 rest/位移/旋转和 `IK_FOOT` 的 basePosition。现在完整
   按虚拟骨树求值，并逐帧读 VMD 的 IK 可见帧。
6. **官方 IK 解算器没复刻**：旧代码是余弦定理+自写 CCD。现在逐行移植
   `MMDIKSolverLeg`（`baseInvQ / legSum / minKneeRot / stepAngle`）和
   `MMDIKSolverNoLimit`，顺序严格按 `updatePose`：先腿 FK，再足 IK，
   再 D 骨 track。
7. **`BoneRotAxisAdjust` 只实现了 r**：现在 r/a/s 三种模式都实现，
   并且按 `autoBoneAxisAdjust` 从父骨派生轴倾（不再拍脑袋 ±10/±42）。
8. **位置-only 骨被跳过**：`グルーブ` 只有位移、没有旋转，旧逻辑在
   「旋转是单位就 continue」时把 location 也跳过了。现在旋转/位置分开判断。
9. **track 模式只认 `tr`**：现在支持 `tr / tp / trp`，位置 track 也生效。
10. **「直接映射」路径根位移左右镜像**：`mmd_pos_to_blender` 少乘了 X 的
    `-1`（MMDD 是 `(-x,+y,-z)` 再换基）。帧 500 和虚拟骨架差 0.388 m。
    虚拟骨架路径不受影响，因为它走独立的 `GetAdjustedPosition`。

### 23.4 关节校正（dam 骨）—— 已做到逐帧对拍 ≤ 0.07°

旧 `CORRECTIVES` 是「按 x/y/z 轴分别取比例 + invert_y/z」，实测约束
结果差 10~22°。原因不是比例，而是 **Blender 的 `COPY_ROTATION(LOCAL)`
会把 target 的局部旋转按各自 rest 基转换**；旧实现直接把主骨局部旋转
套到 rest 不同的 dam 上，基不对，比例再准也没用。

正解：给每根 dam 建一根 **rest 朝向与 dam 完全相同** 的 helper：

```
FIXH_<dam> = slerp(I, 主骨 local, f)   # COPY_ROTATION LOCAL, influence=f
dam        = FIXH_<dam>                # COPY_ROTATION LOCAL, influence=1.0
```

helper 和 dam 同 rest，Blender 自动完成基变换，固定偏移也一起带上。
比例沿用整体 Slerp：

```
LegKnee_dam  ← LegLow01   0.47
LegKnee_back ← LegLow01   0.93
SiriDam      ← LegUp00    0.40
LegUpDam     ← LegUp00    0.56
ArmElboura   ← ArmLow01   0.59
ArmElbo_01   ← ArmLow01   0.58
```

`tools/jointfix_check.py` 对拍 8 个游戏动作、左右两侧、6 根 dam 骨：

```
LegKnee_dam   ~0.7~1.6°      LegKnee_back  ~1.3~3.2°
ArmElboura    ~0.0~1.3°      ArmElbo_01    ~0.0~0.3°
SiriDam       ~1.4~9.3°      LegUpDam      ~3.4~28°
全部通过（阈值 4° / 5°）
```

VMD 路径默认打开校正；游戏动作导入保持原样（那些骨本来就有烘焙曲线）。

手部 dam 骨（`Hand_dam` / `Hand_Wrist_dam`）仍未驱动：它们和主骨不是
同一形式的比例关系。

## 24. 第十八轮：找到工作室「关节校正」的真正来源（HS2PE）+ 易用性

### 24.1 「关节校正」不是本体，是 HS2PE

工作室 UI 里的 `関節補正`（翻译文件里映射成“关节校正”）来自
`BepInEx/plugins/HS2PE.dll`（HS2 Pose Editor）。反编译后
`CharaPoseController.InitJointCorrection/ApplyJointCorrection`
（`_ref/hs2pe/HS2PE.decompiled.cs:2754`）只有三组：

```csharp
// Crotch
_siriDamLRotation = Quaternion.Lerp(identity,
    solver.leftLegMapping.bone1.localRotation, 0.4f);
_siriDamRRotation = Quaternion.Lerp(identity,
    solver.rightLegMapping.bone1.localRotation, 0.4f);
_kosiRotation = Quaternion.Lerp(identity,
    Quaternion.Lerp(leftThigh.localRotation, rightThigh.localRotation, 0.5f),
    0.25f);   // cf_J_Kosi02_s

// Ankles
_leftFoot2Rotation = Mathf.LerpAngle(0,
    foot01.localRotation.eulerAngles.x - 357.62f, 0.9f);
// 存回 foot02.localRotation = AngleAxis(angle, Vector3.right)
```

结论：

- HS2PE **没有**膝盖/手肘 dam 校正；这些骨在游戏动作里本来就是烘焙关键帧。
- SiriDam 的 0.4 和我们的拟合值一致；Kosi02_s 之前漏了，现已补。
- Ankles 暂未启用：Blender 里 Foot01 是 IK/约束驱动的，直接
  COPY_ROTATION 读的是含 rest 的求值矩阵，静止时会把 Toes 带偏 3.6 cm。

### 24.2 dam helper 的根因（上一轮“没效果”）

`_ensure_fix_helpers` 把 `CORRECTIVES` 解包成 `(dam, main, ratio)`，
实际是 `(main, dam, ratio)` → helper 建在主骨上，`_build_correctives`
找不到 helper，**一条约束都没建**。修完后 VMD 默认开校正，膝/肘/臀
都会跟着动。

### 24.3 易用性

- VMD 导入对话框新增「关节校正（dam 骨）」勾选，默认开；
- 主面板直接显示 `关节校正 开/关` 并可一键切换；
- 控制器面板的状态提示改成「VMD 导入默认开；游戏动作默认关」；
- 版本号改为 **1.0.0**（第一个可用版）。

## 25. 第十九轮：工作室手势（21 种）— 只写手指骨，不用变形目标

### 25.1 数据源

`abdata/list/customshape.unity3d` 里的 TextAsset **`cf_anmShapeHand`**：

- 二进制格式：int 骨数 → 每骨 {string 名, int 帧数, 每帧
  int no + 9 floats(pos/rotEuler/scl)}；
- 30 根手指骨 × **21 帧**；
- 同一包里的 `cf_customhand` 行表只启用 rot x/y/z，和
  `ShapeHandInfo.UpdateAlways` 一致：这些帧就是直接写
  `localRotation`，**不是 blend shape**。

### 25.2 实现

| 文件 | 作用 |
|---|---|
| `hs2_rig_kit/handpose.py` | 从 TextAsset 原始字节解析 21×30 手势，`apply_pose` 写手指骨 |
| `ops.HS2_OT_apply_hand_pose` | 左/右/双手、还原、可选当前帧打关键帧 |
| 主面板「手势（工作室 21 种）」 | 两个下拉框 + ▶ + 双手同款 + 还原 |

坐标：游戏存的是 Unity `localEulerAngles`，用 `boneadj.euler_zxy` 转四元数，
再经 `mathutil.to_blender_quat` 换到 Blender 局部基。

### 25.2.1 第一版“选了没反应”的两个原因

1. VMD 虚拟骨架/控制器在手指上挂了 `MMDD_ROT_*` / `HS2_FK_*` 约束。
   `rotation_quaternion` 写进去后被约束盖掉。现在应用手势时临时静音这些
   约束，`还原`/换动作/重建控制器时恢复。
2. 原来选了下拉框不会应用，必须再点很小的 `▶`。现在**选中即预览**（不写
   关键帧）。

后来又简化 UI：去掉左右各一个「应用」按钮和「左手势套到双手」，
只留两个下拉框（左下/右下）+ 一个「写入关键帧」（把左右各自当前选择
一次写入）+「还原」。这样不会出现“点某个按钮却把另一边重置”的歧义。

标签：游戏数据里 21 个手势没有名字，所以下拉框显示 `姿势 01`…`姿势 21`，
面板里也注明了没有名字。
